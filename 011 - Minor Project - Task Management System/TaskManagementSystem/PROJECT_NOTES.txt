Task Management System - Project Notes
======================================

Reference used:
- Minor Project-part1-11.pdf

Project purpose:
This Django project is a Task Management System. It allows users to add tasks,
view tasks, update tasks, mark tasks as completed, move completed tasks back to
pending, delete tasks, search/filter tasks, view dashboard statistics, and manage
records through Django Admin.

Part 2 - Task Model and Database
--------------------------------

Purpose:
Create the database structure for storing task records.

Files used:
- tasks/models.py
- tasks/admin.py

Model used:

   class Task(models.Model):
       title = models.CharField(max_length=150)
       description = models.TextField()
       completed = models.BooleanField(default=False)
       created_at = models.DateTimeField(auto_now_add=True)

Fields:
- title: stores task name.
- description: stores task details.
- completed: stores task status. False means pending, True means completed.
- created_at: stores task creation date and time automatically.

Commands:

   python manage.py makemigrations
   python manage.py migrate

Admin setup:
- Register Task model in tasks/admin.py.
- Show title, completed status, and created date in Django Admin.
- Add filter by completed status.
- Add search by title.

Open admin:

   http://127.0.0.1:8000/admin/


Part 3 - Display Tasks From Database
------------------------------------

Purpose:
Fetch task records from the database and display them on the website.

Files used:
- tasks/views.py
- tasks/urls.py
- templates/tasks/task-list.html

Main view:

   def task_list(request):
       tasks = Task.objects.all().order_by('-created_at')
       return render(request, 'tasks/task-list.html', {'tasks': tasks})

Important concepts:
- Task.objects.all() gets all task records.
- order_by('-created_at') shows newest tasks first.
- Template loop displays each task.
- If no tasks exist, show a message.

Open:

   http://127.0.0.1:8000/tasks/

Pending tasks:

   http://127.0.0.1:8000/tasks/pending/

Completed tasks:

   http://127.0.0.1:8000/tasks/completed/


Part 4 - Add Tasks Using ModelForm
----------------------------------

Purpose:
Allow users to create tasks from the website instead of only using Django Admin.

Files used:
- tasks/forms.py
- tasks/views.py
- tasks/urls.py
- templates/tasks/task-form.html
- templates/tasks/task-list.html

Form used:

   class TaskForm(forms.ModelForm):
       class Meta:
           model = Task
           fields = ['title', 'description']

Important concepts:
- ModelForm creates a form from the Task model.
- form.is_valid() checks submitted data.
- form.save() saves the task to the database.
- redirect('task-list') returns the user to the task list.
- csrf_token protects the POST form.

Open:

   http://127.0.0.1:8000/tasks/create/

Test task creation:
1. Open the create page.
2. Enter title and description.
3. Click Add Task.
4. The new task appears in the task list.


Part 5 - Update Tasks Using ModelForm
-------------------------------------

Purpose:
Allow users to edit an existing task instead of creating a duplicate task.

Files used:
- tasks/views.py
- tasks/urls.py
- templates/tasks/task-form.html
- templates/tasks/task-list.html

Important concepts:
- get_object_or_404(Task, id=task_id) finds the selected task.
- TaskForm(instance=task) loads existing data into the form.
- TaskForm(request.POST, instance=task) updates the same record.

Open example:

   http://127.0.0.1:8000/tasks/4/edit/

Create vs update:
- Create uses TaskForm(request.POST).
- Update uses TaskForm(request.POST, instance=task).

SQLite Commands For Current Database
------------------------------------

Open the SQLite database:

   sqlite3 db.sqlite3

Show all tables:

   .tables

Show all task records:

   SELECT id, title, description, completed, created_at
   FROM tasks_task
   ORDER BY created_at DESC;

Count total tasks:

   SELECT COUNT(*) FROM tasks_task;

Count completed tasks:

   SELECT COUNT(*) FROM tasks_task WHERE completed = 1;

Count pending tasks:

   SELECT COUNT(*) FROM tasks_task WHERE completed = 0;


MySQL Note
----------

The current project is configured for SQLite. MySQL will not show the existing
10 task records unless the project is changed to use MySQL and the data is
migrated or inserted there.

If MySQL is used later, Django migrations will create tables such as:
- auth_group
- auth_permission
- auth_user
- django_admin_log
- django_content_type
- django_migrations
- django_session
- tasks_task
